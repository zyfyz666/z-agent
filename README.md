# Z

Z 是一个面向长程任务的桌面编程 Agent，将对话、项目操作、工具执行和代码审查放在同一个界面中。内置的 **「观察者」** 结合任务目标、工具行为和验证记录，为执行中的 Agent 提供纠偏提醒，帮助模型在长时间、多步骤的工作中保持全局视野。

## 观察者：帮助模型保持长程任务的全局视野

长程任务往往包含多轮探索、修改和验证。随着执行步骤增加，模型可能困在某个局部问题里：反复查看相同内容、沿用缺少进展的方案，或者继续依赖修改前的测试结果。

**观察者的核心价值，是帮助模型提高长程任务中的全局视野。** 它把近期行动放回原始目标和已有执行证据中检查，在出现停滞信号时提醒模型重新审视方向、调整策略，并保留已经验证的成果，让后续工作继续围绕整体任务推进。

观察者关注以下几类信号：

- **目标偏移**：近期行动反复重复、又缺少与原始目标的关联时，提示模型重述目标，核对当前工作是否仍在服务于它。
- **重复与信息停滞**：识别重复操作，以及持续围绕已探索内容打转、缺少新信息的情况，减少无效尝试。
- **策略固化**：当方案变化很小、进展又长期不足时，提醒模型改变策略，或给出继续当前路线的依据。
- **验证过期**：发现通过检查后又修改了代码，提示重新验证，避免把旧的成功结果当作当前状态。

确认后的提醒会送入正在执行的 Agent，作用于后续工作，并要求保留已经验证的成果，避免没有具体理由地重复执行。

**先确认，再提醒。** 模型观察默认保持安静，只有依据任务目标和近期行动，明确确认主 Agent 已经进入误区时才提出纠偏建议，并提供可追溯的行动证据。正常探索、一次失败、耗时较长或观察者个人偏好的不同，都不能单独成为提醒理由。启用模型观察后，规则信号只作为待核验线索，不会绕过模型直接插话；模型不可用时继续记录规则状态，暂停未经确认的提醒。

**执行过程可见。** 观察者面板默认展开，展示当前任务的运行状态、触发原因、提醒投递情况和事件历史。你可以手动关闭或从侧栏重新打开；任务更新或切换会话不会强制打开已经关闭的面板。面板使用真实运行事件。

**记录跟随对话。** 打开一个对话，观察者会恢复该对话的记录；在面板的「观察记录」中可以选择具体轮次，较早的轮次可按需加载。模型判断无需介入时，也会留下「判断为不介入」、判断时间和理由，不增加介入次数。查看历史时，后台任务不会覆盖所选记录。已保存的记录在重启后仍可查看；每轮保留检查计数、最近的模型判断和最近 30 条观察记录。没有保存观察者数据的旧轮次会明确显示「此轮没有监控记录」。

**没有新动作，也会巡检。** 独立的「运行巡检」每 20 秒检查一次真实进展，不把连接心跳当成模型在工作。工具超过自己声明的时限时会复核状态，显示超时工具、最近进展和巡检记录；等待用户回答或授权会单独标明。没有明确时限的长任务只标为状态待核实，不因耗时就判断主 Agent 走偏。巡检无需额外调用模型，不增加模型判断或介入次数，也不会擅自重放可能已经执行的操作。

**两种观察方式。** 默认使用确定性规则，无需调用模型，按规则触发提醒。也可以在输入框下方点击「观察者」，为它单独选择 API 和模型，与主 Agent 的连接互不影响。模型只接收任务目标和近期行动摘要，在后台核验，不执行工具。模型观察会产生所选服务的调用费用。

**独立思考强度。** 在观察者的模型选择下方，可设置「轻度、中、高、极高、最高」五档，默认「最高」。设置会按所选模型支持的档位映射到实际请求，与主 Agent 的思考强度互不影响；仅规则模式不调用模型，因此不使用此设置。修改从下一轮任务生效。

**细节模式。** 在观察者设置中展开「细节模式」，可设置每新增 **1–100 个工具动作**检查一次，默认 **6**。这里的动作指读文件、执行命令等工具操作，不是聊天消息；规则首次判断至少需要 6 个动作。模型判断期间不会重复发起请求，主任务结束后取消未完成的观察。设置从下一轮任务生效。

**收尾核验与唤醒。** 选择了观察者模型时，每轮任务自然结束后（不是你点了停止或结束），观察者会对照你最近一次提出的目标，核验主 Agent 的最终回复、待办、近期行动、验证和改动文件，判断为「已达成」「等待你的回复」「无法确认」或「未完成」。判断未完成且无需你介入时，观察者会写一条续做指令：默认 15 秒倒计时后自动唤醒主 Agent；剩余工作需要等外部过程（训练、下载、部署等）时，它会安排 1 分钟到 24 小时后再唤醒。唤醒消息在对话中带「观察者唤醒」标记。面板里可以「立即唤醒」或「取消」；你自己发消息会接手并取消待执行的唤醒。同一目标默认最多连续唤醒 **3** 次（设置中可改为 1–10），到上限后交给你决定。定时唤醒到点时 Z 若是关着的，下次打开显示「已过期」，点一下再唤醒，不会自动补跑。规则模式无法判断目标是否达成，不提供此功能；每轮会多一次观察者模型调用，可在观察者设置中关闭。

## 更多功能

- **项目与任务**：无需先选择工作区即可对话、生成文件和执行任务。Z 会为每个对话创建独立的持久任务文件夹；也可以选择已有项目，修改代码和查看变更。跨目录操作沿用当前权限设置，无需仅为切换目录新建对话。
- **上下文管理**：点击右侧上下文圆环，再点击面板标题旁的箭头，即可为当前对话设置自动压缩界限。支持输入 K tokens、拖动百分比滑杆和恢复默认值；各对话独立保存。运行中的任务保留本轮界限，修改从下次发送生效，已排队的任务使用提交时的设置。
- **数学公式**：回答支持 `$…$`、`$$…$$`、`\(…\)` 和 `\[…\]` 的 LaTeX 数学排版，公式与字体在本地渲染。代码块保留源码，流式文本在该段输出完成后排版。
- **模型接入**：在设置中添加模型服务，然后点击输入框右下角的模型按钮，在同一个菜单里选择供应商和模型，也可调整推理强度。展开的菜单为模型列表保留独立滚动区域，长模型名称自动换行，小窗口也能滚动查看全部设置。每个对话独立保存主模型，切换一个对话的模型不会影响其他对话；正在执行的轮次继续使用启动时选定的模型。
- **思考强度**：每个对话独立保存档位，切换对话时恢复各自的选择，不影响其他对话。运行中和已排队的任务使用提交时保存的档位。Claude 4.7 的 Anthropic 通道会启用自适应思考并传递对应的 effort 档位。较高档位表示希望模型投入更多思考，不保证固定思考时长。
- **排队与引导**：任务执行期间，按 Enter 或点击发送默认排队，也可以手动点击「引导」，将文字和附件加入当前任务。「等待引导」表示尚未确认送入模型；后续真实请求携带该指令，并被接口成功接收后显示「已经引导」。这表示请求已送达，不保证模型一定遵循。引导按发送时间插入回复之间，切换对话、重启或创建分支后仍保留顺序和状态。有排队消息或等待引导时，点击中止会停止当前执行，保留已完成的工作记录，再自动发送待处理内容；输入框里尚未发送的草稿会保留。技能和子代理选择使用排队方式。
- **对话独立提问**：提问和权限确认只在所属对话中显示。后台任务会标记「待回答」或「待确认」，切回后恢复问题、已选答案和填写草稿；不同对话的请求不会互相覆盖。
- **对话浏览器**：每个对话独立保存浏览器标签页、网址和选中的页面，切换回来或重启后可以恢复。共享同一个项目目录的对话也不会串页；后台任务的浏览器操作留在所属对话中。
- **最近对话与快捷改名**：侧栏「最近」按更新时间汇集不同项目的对话，支持展开更多和折叠。右键任意对话或点击「⋯」即可重命名，无需打开它；改名不会打断当前对话，后台继续保存也会保留新名称。
- **对话存储位置**：右键侧栏任务或点击任务旁、顶部的「⋯」，选择「对话存储位置」，即可查看该任务对话记录文件的完整路径、复制路径，或在文件夹中定位该文件。查看其他任务的位置无需切换当前对话。
- **从消息创建分支**：在已保存消息的工具栏点击「从这里创建分支」，保留到该消息为止的对话及观察者历史，在独立对话中继续。新分支显示来源，可返回原对话；后续消息互不影响。分支共享当前工作区文件，不会回滚文件或复制正在执行的任务。首次继续会完整恢复分支历史；若超过所选模型的上下文上限，会明确提示，完整记录仍保存在分支中。
- **对话回退**：在用户消息的工具栏选择「回退到这里」，会将这条消息及附件放回输入框，允许自由修改后重新发送，模型上下文回退到该消息之前。回退到中途引导时，保留发送引导那一刻已有的助手回复和工具执行记录，包括尚未写完的回复；新引导还会保存当时的观察者状态。之后的输出不会进入回退后的上下文。选择助手回复时，保留到该回复为止的记录和观察者历史，可以继续输入新指令。回退前的完整记录会自动备份，集中放在原对话右键菜单的「回退备份」中，可查看或恢复，不占用普通对话列表；真正的分支会单独标记「分支」。恢复时也会备份当前记录。回退只改变对话及模型上下文，项目文件保持当前状态。正在执行或有排队消息的对话需先结束运行、处理队列，再回退。
- **暂停与继续**：点击停止后，保留原始消息、引导记录、已生成的回复和工具执行记录。切换对话或重启后仍可查看，再发消息可沿用原有上下文继续。
- **工具扩展**：通过技能和 MCP 接入更多工具，配合代码审查等工作流完成任务。
- **界面恢复**：默认使用软件渲染，降低对 GPU 和驱动状态的依赖。界面进程意外退出时自动重载，后台任务继续运行；一分钟内连续恢复两次仍失败时显示恢复页，可手动重试或查看诊断日志。恢复界面不会再次提交模型请求。
- **Windows 工具收尾**：命令进程退出后，输出通道只继续收集短暂的尾部内容，避免后台子进程占着通道导致工具永不返回。执行超时后的清理也有上限，保留已收到的输出；已退出的启动命令不会连带终止后台工作。自动重试前必须确认原请求已结束且没有结果不明的工具操作。

## 开始使用

源码运行环境：**Windows x64 或 macOS arm64，Node.js 22**。

```bash
git clone https://github.com/zyfyz666/z-agent.git
cd z-agent
npm ci
npm start
```

首次启动后：

1. 在设置中配置模型服务和访问凭据。
2. 新建任务，直接描述你希望完成的工作。
3. 文件默认保存在系统文档目录下的 `Z Agent/Tasks/<会话 ID>`；处理已有项目时，可在任务开始前选择项目文件夹。
4. 在对话中查看执行结果，通过观察者面板查看运行状态。

模型配置、会话和历史记录保存在 `%APPDATA%\Z\ZData`（macOS 为 `~/Library/Application Support/Z/ZData`），内置浏览器登录状态保存在同一 `Z` 目录下。

## 开发与构建

```bash
npm run dev             # 开发模式
npm test                # 单元测试
npm run build           # Windows 安装包
npm run build:portable  # Windows 便携版
npm run build:mac       # macOS arm64 镜像，需在 macOS 上构建
```

构建产物输出到 `dist/`，应用名称为 **Z**。

## 观察者高级设置

可通过环境变量调整观察者的运行规则：

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `WD_WATCHDOG` | 开启 | 设置为 `0` 可关闭观察者的运行干预 |
| `WD_WATCHDOG_N` | `6` | 无界面配置的运行入口使用此间隔；桌面端以观察者设置为准 |
| `WD_WATCHDOG_HALT` | 关闭 | 设置为 `1` 时，持续停滞可触发结束运行的请求 |
